# PSLC Agent

Экспериментальная система поддержки и администрирования Windows/Linux: разбор проблемы, подготовка плана, подтверждение, выполнение узловым агентом и проверка результата.

Версия исходников: **0.18.2**. Код не является подтверждением готовности к production. Реальная сеть, права служб, TLS/PKI, модели и корпоративные допуски требуют отдельной проверки.

## Безопасность первого запуска

В новой пустой базе создаётся **admin/admin** с широкими административными правами. **Обязательно смените этот общеизвестный пароль до сетевого использования.** До этого работайте только через loopback. Не публикуйте административный интерфейс в Интернет. Перезапуск не сбрасывает существующий пароль.

Модель предлагает план, но не получает самостоятельного разрешения выполнять команды. Подтверждение точного плана, права пользователя и независимые разрешения узла сохраняются. Неизвестный исход требует сверки, а не слепого повтора.

## Разработка из исходников

Нужны Python 3.12+ x64 и Node.js с pnpm. Создайте отдельное виртуальное окружение, установите зависимости из requirements.lock.txt, затем выполните pnpm install --frozen-lockfile и pnpm build. Для Python-тестов: python -m pytest. Синхронизация справки: python scripts/generate_product_guides.py --check.

Git checkout не содержит собранный Web, runtime, native binaries или веса модели. Не путайте его с готовой установочной поставкой. Загружайте готовые архивы только после отдельной проверки состава и SHA256. Исторические bundles, не прошедшие проверку публичной поставки, недоступны как готовый публичный релиз.

## Возможности и ограничения

- Диалоги, точный выбор устройств, подтверждаемые планы и проверка результата.
- Подключение агентов Windows/Linux, ограниченное обнаружение частной IPv4-сети.
- Локальные учётные записи, роли и области доступа.
- Локальная CPU-модель или настроенный OpenWebUI; качество ответов требует проверки.
- Подготовленный откат объявленных ресурсов и согласованные расписания. Полное восстановление ОС не гарантируется.
- Один процесс API. Тестовые сценарии не подтверждают масштабирование или доступность production.

Журналы, полный вывод команд и контекст модели остаются в ограниченной RAM. Типизированные метаданные, зашифрованный baseline узла и явно сохранённые шаблоны расписаний имеют отдельные правила хранения.
