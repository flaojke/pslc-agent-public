# software-installation Specification

## Purpose
Обеспечивает установку утверждённого ПО на выбранном узле по точному подтверждённому плану с проверкой целостности дистрибутива и установленной версии.

## Requirements

### Requirement: SI-001 Approved catalog
Система SHALL разрешать только пакет/версию/ОС из административного каталога с URL, SHA-256, тихими параметрами, проверкой версии и инструкцией удаления. Каталог MUST быть read-only для UI/модели; пустой или некорректный каталог не разрешает установку.

#### Scenario: Unknown or incompatible package
- **WHEN** пакет отсутствует, запись некорректна или ОС узла не совпадает
- **THEN** план установки не создаётся и агент не получает произвольную команду

### Requirement: SI-002 Admission and exact confirmation
Установка SHALL требовать отдельного opt-in узла и подтверждения плана с целью, версией, источником, SHA-256, параметрами, проверкой и timeout. Перед выдачей MUST проверяться актуальность записи каталога; её изменение/удаление инвалидирует план.

#### Scenario: Changed catalog
- **WHEN** после подтверждения изменён источник, хеш, версия, проверка или параметры пакета
- **THEN** задание не выдаётся до подготовки и подтверждения нового плана

#### Scenario: Disabled installer capability
- **WHEN** узел не разрешил установки
- **THEN** установка не выдаётся независимо от разрешения обычных команд

### Requirement: SI-003 Artifact integrity
Исполнитель SHALL загружать только утверждённый URL без перехода на другой источник, ограничивать объём/время и проверять SHA-256 до запуска. Несовпадение хеша или ошибка загрузки MUST запрещать запуск; временный артефакт удаляется по завершении.

#### Scenario: Hash mismatch
- **WHEN** загруженные байты не соответствуют SHA-256 плана
- **THEN** установщик не запускается и результат integrity_failed не считается успехом

#### Scenario: Redirect or oversized artifact
- **WHEN** источник перенаправляет запрос или превышен лимит размера/времени
- **THEN** загрузка прерывается без установки

### Requirement: SI-004 Verified version and idempotence
Исполнитель SHALL проверять точную целевую версию до и после установки. Совпадающая исходная версия MUST давать already_installed без повторной установки. Код успеха без совпавшей итоговой версии MUST давать verification_failed.

#### Scenario: Desired version already exists
- **WHEN** начальная проверка подтверждает нужную версию
- **THEN** установщик не запускается и возвращается already_installed с проверенной версией

#### Scenario: False successful installer
- **WHEN** установщик вернул 0, но постпроверка не подтвердила версию
- **THEN** задача завершается verification_failed, а не verified

### Requirement: SI-005 Reboot and uncertain effects
PSLC Agent MUST не инициировать reboot. Требование перезагрузки SHALL отображаться отдельно; timeout/потеря определённости после запуска установщика MUST удерживать outcome_unknown без слепого повтора. Откат/удаление MUST не исполняться автоматически.

#### Scenario: Reboot required
- **WHEN** установщик сообщает требование перезагрузки и версия подтверждена
- **THEN** результат reboot_required виден оператору без запуска команды перезагрузки

#### Scenario: Installer timeout
- **WHEN** после запуска установщика истёк timeout
- **THEN** результат outcome_unknown требует сверки и не освобождает узел для повторной установки вслепую

### Requirement: SI-006 Reviewable UI and retained data
UI SHALL показывать пакет/версию/цель, источник/хеш, установку, проверку и порядок удаления до подтверждения. История SHALL хранить только типизированные сведения пакета и проверки без исходного вывода; лимиты 5/20 сохраняются.

#### Scenario: Review and reject
- **WHEN** оператор отклоняет показанный план установки
- **THEN** запуск не происходит и отказ учитывается в общей статистике

### Requirement: SI-007 Compatible upgrade
Обновление SHALL сохранять существующие узлы, credentials и задачи. Новое право установки у старых узлов MUST оставаться выключенным; неизвестная версия схемы MUST не изменяться автоматически.

#### Scenario: Existing v1 database
- **WHEN** сервер обновляет схему v1
- **THEN** старые данные доступны, installations_enabled=false и незавершённое действие не повторяется

### Requirement: SI-008 Restorable package presence
Новая установка SHALL иметь утверждённые uninstall argv/timeout и отдельный absence proof в каталоге. Baseline SHALL доказать отсутствие пакета; уже нужная версия даёт no-op, другая/неопределённая версия без restore contract блокирует установку. Ручной undo SHALL проверять absence и не называться полным восстановлением ОС.
#### Scenario: Missing package recovery
- **WHEN** каталог не содержит проверяемого recovery provider
- **THEN** пакет можно просмотреть, но установка не допускается
#### Scenario: Restore new installation
- **WHEN** после новой установки подтверждён ручной rollback
- **THEN** выполняются только frozen uninstall/absence check с installation opt-in; отсутствие proof не является восстановлением
