# device-enrollment Specification

## Purpose
Управляет идентичностью узлов PSLC Agent и их допуском к получению заданий без общего постоянного секрета всего парка.

## Requirements

### Requirement: DE-001 One-time enrollment
Оператор SHALL выдавать одноразовый ограниченный по сроку enrollment token. Узел MUST обменять его на уникальный credential; сервер MUST хранить только хеши секретов и назначать устойчивый ID. Новое подключение сверх 500 устройств MUST отклоняться.

#### Scenario: Token replay
- **WHEN** enrollment token уже использован или просрочен
- **THEN** повторное подключение отклоняется, новый узел не создаётся

#### Scenario: Device cap
- **WHEN** в реестре уже 500 устройств
- **THEN** следующий enrollment отклоняется без частичной записи

### Requirement: DE-002 Revocation and identity
Задания и результаты SHALL связываться с ID и credential узла, а не hostname. Отозванный узел MUST не получать задания и не изменять результаты; одно имя у двух узлов MUST не смешивать их данные.

#### Scenario: Revoked agent
- **WHEN** оператор отозвал узел и агент делает poll
- **THEN** сервер возвращает отказ и не выдаёт действие

#### Scenario: Foreign result
- **WHEN** другой узел пытается завершить чужое задание
- **THEN** результат не принимается

### Requirement: DE-003 Freshness
Система SHALL различать последнее наблюдение и текущую доступность; heartbeat MUST не объявлять ранее собранные сведения актуальными повторно.

#### Scenario: Stale node
- **WHEN** heartbeat отсутствует дольше заданного интервала
- **THEN** устройство отображается как неактуальное с временем последней связи
