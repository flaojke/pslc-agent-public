# Сканирование сети и подключение кандидатов

Войти администратором с доступом ко всему парку. «Устройства» → «Сканировать сеть». Открытие формы не создаёт сетевых соединений. Выбрать активную частную IPv4 сеть сервера и явно указать CIDR внутри неё. На запуск — не более1024 адресов; большую подсеть нужно явно сузить. Публичные, loopback, link-local и multicast диапазоны не принимаются.

«Проверить выбранный диапазон» запускает до64 TCP connect одновременно, по0,5с на попытку, с общей границей90с. Фиксированные порты:22,135,139,445,3389,5985,5986,8787. Вход по паролю, чтение баннеров, поиск уязвимостей и команды не выполняются. TCP open/refused — сетевой отклик, а не доказательство ОС или роли машины. Firewall может скрыть узлы; полнота инвентаризации не гарантируется.

Виден прогресс, частичные кандидаты и «Остановить сканирование». После отмены новые проверки прекращаются, уже начатые заканчиваются в пределах таймаута. Результат хранится в RAM15минут; при повторном открытии формы доступны свои недавние проверки. После рестарта scan не возобновляется. Другой администратор не читает чужой результат по ID.

Кандидат не входит в управляемый парк и не получает заданий. «Подготовить подключение» открывает профиль: ОС надо выбрать явно, тип по умолчанию не указан, исполняемые разрешения выключены. IP не доказывает identity: проверьте, не управляется ли машина уже под другим именем.

Создать профиль, скачать установочный ZIP, отдельно получить одноразовый код. Установка и enrollment выполняются на выбранном узле. Только после успешной регистрации обычным bound-профилем появляется managed device. Лимит500 и правила5/20 сохраняются.

Реальный LAN scan при разработке не выполнялся: проверены подставные probes и реальный браузер. Сетевой допуск ИТ/ИБ для фактических диапазонов и production остаётся отдельной приёмкой.

Реализация использует стандартные [asyncio streams](https://docs.python.org/3.12/library/asyncio-stream.html) с таймаутом и закрытием соединений; административные команды не передаются удалённым машинам.
