# Выбор и проверка модели

Выбирайте модель под конкретные разрешённые задачи, аппаратные ресурсы и поддерживаемый формат ответа. Каталог локальных моделей и их контрольные суммы находятся в config/local-models.json. Параметры и лицензии проверяются для точного checkpoint и отдельно для runtime; лицензия проекта не заменяет лицензию весов.

Для OpenWebUI укажите свой HTTPS-адрес, разрешённый model ID и ключ с необходимыми правами через защищённый интерфейс. Получайте фактические IDs через API, а не по отображаемому названию. Не помещайте ключи в исходники, ссылки или сообщения. См. OPENWEBUI_CONNECTION_GUIDE.md.

Проверяйте выбранную модель на одинаковых обезличенных сценариях: неоднозначные устройства, отсутствующие сведения, разбор событий, безопасный код, точные постусловия, отказы и prompt injection. Измеряйте корректность JSON, выбор целей, необходимость уточнений и задержку на целевом оборудовании. Простой успешный connectivity probe не подтверждает качество планирования.

Критический критерий: модель не должна обходить права, ограничение целей и подтверждение действий, либо утверждать об исполнении без проверенного результата. Ответ модели остаётся гипотезой; приложение валидирует план и требует предусмотренное подтверждение.

Нагрузку, память, лицензии, доступность сети и правила хранения провайдера проверяйте в конкретной установке. Табличные benchmark и число активных параметров не доказывают пригодность к административным задачам или достаточность памяти. Ни одна модель не получает дополнительной автономности только из-за её выбора.
