# Эксплуатация и восстановление — 0.10.0

Рекомендуемый пилот: отдельный сервер/VM API+PostgreSQL, inference endpoint отдельно. Это отделяет доступность от рабочего места администратора и упрощает резервирование/права. Текущая поставка по-прежнему loopback/local-development; сетевой ingress и production допуск требуют выбранных адресов, PKI и ИБ. Для локальной разработки SQLite допустим. Один API process: планы/сессии/контекст RAM, горизонтальное масштабирование не поддержано. 5 active per owner+session,20 fleet,500 registry; guard PostgreSQL SELECT FOR UPDATE сериализует admission.

Подключение: PSLC_DATABASE_URL=postgresql+psycopg://... в приватном окружении, не в командной строке и репозитории. PostgreSQL18.6 проверен в отдельном Docker loopback55433, не корпоративный кластер. compose.yaml — общий dev template18, QA использует отдельные container/volume и pinned image digest. Существующие базы/volumes не удалялись. 500 узлов — synthetic registrations, не нагрузочный пилот500 реальных машин.

Backup: `python -m backend.operations backup --output <новый защищённый путь>`. Команда читает metadata в REPEATABLE READ readonly PostgreSQL / consistent SQLite snapshot, проверяет точную schema6/tables/columns/JSON allowlists. Не запускает Store lifecycle и не меняет состояния источника. Формат pslc-metadata-v1,128MiB/100000rows per table; файл создаётся эксклюзивно0600 + sha256 sidecar. Windows следует заранее назначить NTFS ACL директории только backup/service владельцу. Snapshot содержит device credential hashes и operator opaque IDs, его необходимо защищать; raw logs/code/JWT/source credentials/config туда не входят. Hash обеспечивает integrity, не authenticity/encryption: хранить digest по доверенному каналу, шифрование/retention storage согласовать с ИБ.

Restore: остановить API/агенты выбранного контура; создать НОВУЮ пустую БД; установить PSLC_DATABASE_URL target приватно; `python -m backend.operations restore --input <snapshot> --expected-digest <доверенный SHA256>`. Никогда не направлять на существующую базу: инструмент откажется без drop/overwrite. Полная валидация передDDL, данные одной транзакцией. При ошибкеDDL может остаться пустая новая schema — следующий повтор на другой пустой target. Результат не исполняет ни одного действия. Running/cancel_requested/outcome_unknown→outcome_unknown с недействительной старой lease; pending планы истекают; analysis context_lost. Identity hashes/history сохраняются. Конфигурация, trust keys, CA и IdP policies восстанавливаются отдельно из принятого secret/config management. Проверить узлы/credentials и фактические эффекты; неизвестные исходы сверить вручную до новых действий.

Контроль: /healthz — версия/режим; /readyz — local API+DB/schema, external acceptance pending; /api/operations/status только platform_admin, без DSN/секретов/сырых payload. В UI «События» администратор видит DB/cache status. Configured-unverified model/Confluence не считается connection test. При DB outage фиксированный503 database_unavailable.


Evals: `python scripts/run_evals.py --postgres-config .local/postgres-qa.json`. A01–A08 selections в qa/scenarios.json. JSON и JUnit содержат только names/status/duration/counts/commands, без captured stdout/traceback/payload. Source fingerprint позволяет видеть устаревшую проверку. Без explicit QA PG configuration PostgreSQL cases skipped/partial, не passed. Автоматизированные fixtures не заменяют corporate acceptance; реальный fault A02 создаётся только на выделенном стенде.

Официальные источники: [PostgreSQL locks](https://www.postgresql.org/docs/18/explicit-locking.html), [backup/pg_dump](https://www.postgresql.org/docs/18/app-pgdump.html). Portable JSON snapshot экспортирует только контрактные application metadata; это не полный PostgreSQL disaster recovery/PITR/roles backup. Для enterprise DR дополнительно принять pg_dump/PITR/roles/PKI procedures и проверить восстановление в корпоративной среде.

Настройка отключённого по умолчанию сетевого пилота: [PILOT_NETWORK.md](PILOT_NETWORK.md). Код не включает его по результатам preflight.

С0.10 snapshot включает salted account password verifiers/typed grants и enrollment profiles; plaintext passwords/session cookies отсутствуют. Restore принимает schema6 и известный metadata snapshot5 с безопасным добавлением пустого реестра accounts. При первом запуске accounts пустого реестра создаётся admin/admin; существующие account verifiers/roles/disable не сбрасываются. Тайминги PostgreSQL46/62ms выше относятся к историческому fixture0.8, не измерению текущего большого реестра.
