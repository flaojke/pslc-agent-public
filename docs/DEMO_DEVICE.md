# Виртуальное демо-устройство
Явная команда администратора сервера: python scripts/create_demo.py. Создаётся ровно1 DEMO-VIRTUAL-WIN-01, с защищённой identity в .local/demo/identity.enc; повтор не создаёт дубликат. Если API уже работает, перезапустите его для загрузки identity. Новая установка имеет пустой inventory, пока команда не выполнена.
Виртуальный симулятор показывает полный поток: «Проверь состояние узла DEMO-VIRTUAL-WIN-01» → план → подтверждение → проверенный демо-результат. Метрики фиксированы: CPU12.5%,RAM37%,свободно128GB. Они не описывают ваш компьютер; результат помечен demo_simulation.
Можно посмотреть/изменить имя с сохранением DEMO-VIRTUAL- prefix и отозвать доступ. Команды, установка ПО и расследования здесь выключены. Это первое health-only демо, не эмулятор полноценной Windows/ПО/журналов.
Симулятор использует обычные scopes, подтверждение, poll/lease/finish и лимиты5/20. Он не импортирует/не вызывает executor, PowerShell, cmd, Python-скрипты или внешнюю модель. Отзыв останавливает выдачу; рестарт не возвращает доступ.
Prefix зарезервирован: реальный enrollment с таким именем не допускается. В metadata backup сохраняются маркировка/source/история, а credential не экспортируется. Без защищённого файла восстановленный узел остаётся offline. Виртуальное демо не является свидетельством приёмки физического Windows/Linux, реального inference или корпоративного пилота.
