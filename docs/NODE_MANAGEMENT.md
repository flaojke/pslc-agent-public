# Подключение и настройка узлов в системе

Узлы заранее неизвестны — список не заполняется демонстрационными машинами или выдуманными IDs. Добавлять Windows/Linux по мере выбора через «Устройства». Предел реестра500, active jobs5/сеанс и20/парк сохраняются.

## Подключение

1. Войти admin / admin либо другой УЗ с platform_admin и нужным device scope. «Устройства»→«Подключить устройство».
2. Задать имя в списке латиницей, ОС, абсолютный путь identity на этой машине и CA при частном TLS. Путь по умолчанию Windows C:/ProgramData/PSLC-Agent/identity.json, Linux /var/lib/pslc-agent/identity.json. Подготовить права директории для выбранной учётной записи процесса.
3. Выбрать разрешения. По умолчанию только health; commands/installations/diagnostics независимы. Нажать «Подготовить подключение».
4. Получить10min одноразовый код (по умолчанию скрыт) и скачать config. Код не входит в config и не хранится сервером открыто. URL берётся из настроенного PSLC_PUBLIC_ORIGIN, поэтому перед удалёнными машинами нужен реальный HTTPS server/public origin;127.0.0.1 работает только на той же машине.
5. Перенести полную проверенную папку агента, config и при необходимости CA на выбранную машину. Native0.7.0 совместим с API0.10.0. Локальные QA binaries находятся в artifacts/native/windows-x64/pslc-agent и artifacts/native/linux-x64/pslc-agent; это QA signing, не корпоративный допуск. Поставка/подпись/служба — AGENT_DELIVERY.md.
6. Windows: `.\pslc-agent.exe --config pslc-agent-windows.json --enroll`; Linux: `./pslc-agent --config pslc-agent-linux.json --enroll`. Уточнить executable bit/защищённые права для Linux. Ввести код скрыто по запросу. Можно использовать Python CLI `python -m agent --config <file> --enroll` из окружения исходников.
7. После регистрации запускать с тем же config без --enroll; для службы использовать принятый service deployment. Identity не перезаписывается при существующем state. В таблице появятся настоящий device ID/OS/freshness. Проверить health.

Профиль ограничивает ожидаемую ОС и потолок разрешений. Агент с другой ОС/лишними flags отклоняется без расходования кода; успешный обмен одноразовый. Имя — только метка, identity определяется выданным ID/credential. Ни форма, ни скачивание config сами не устанавливают агент и не выполняют команду. Не включать повышенные права процесса без необходимости.

## Настройки существующего узла

«Настроить»→изменить имя/серверные разрешения→«Показать изменения»→проверить цель/полный diff/hash→подтвердить. План связан с администратором, device ID и прежним состоянием, живёт300s. Изменённый/чужой/истёкший план требует новой подготовки. Heartbeat не меняет settings hash. Device credential/ID сохраняются; revoked узел не восстанавливается этой формой.

Отключение запрещает ещё не выданные задания и дальнейший анализ при снятом diagnostics допуске. Уже выполняющееся действие может закончиться: изменение permission не объявляется undo/успехом отмены. Включение серверной галочки не меняет локальный config или привилегии учётной записи процесса. Администратор узла отдельно разрешает capability в config и перезапускает агент; без этого агент возвращает disabled. Это защита от неявного расширения возможностей.

«Отозвать» блокирует poll/result credential. Старую identity после отзыва не переиспользовать как новую; новый enrollment — отдельный согласованный шаг. Runtime/ПО не устанавливаются автоматически ради недостающего prerequisites. Исходные журналы/вывод не сохраняются в device settings/history.

## Явный тип устройства в 0.13
В подключении и подтверждаемой настройке выбрать «Пользовательский ПК», «Сервер» или «Не указан». Тип независим от ОС. Старые узлы получают «Не указан» с сохранением ID и прав; в группы ПК/серверов попадут после явной классификации.
