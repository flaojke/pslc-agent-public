# Установка ПО — PSLC Agent 0.2.0

Реализовано по v0.2 VB-EXEC-08/A04. Установки выполняются только из административного каталога, после точного подтверждения и отдельного opt-in агента. По умолчанию каталог пуст, на существующих узлах право выключено.

## Настройка каталога

Файл формата `config/packages.example.json` — только пример, его нулевой SHA-256 и адрес не являются реальным утверждённым пакетом. Создайте свой файл в `.local`, укажите `PSLC_PACKAGE_CATALOG` перед запуском API. Пустой валидный шаблон: `config/packages.empty.json`. UI/LLM не могут записывать каталог.

Обязательны ID, название, версия, ОС, тип msi/exe/deb/rpm, HTTPS URL, SHA-256, проверка версии и инструкция удаления. Для локальных тестов разрешён loopback HTTP; URL с credentials/query/redirects не допускаются. Для MSI silent_args допускает только свойства KEY=value кроме REBOOT/REBOOTPROMPT; тихие/без-restart флаги задаёт драйвер. Для EXE администратор обязан явно указать silent_args и no_restart_args, соответствующие конкретному продукту. Linux-аргументы фиксированы: dpkg --install / rpm --upgrade, без автоматического получения зависимостей.

`verification_argv` — точный read-only способ проверки, `expected_output` — точный stdout.strip(), содержащий утверждённую версию. Качество проверки — часть допуска пакета; проверка строки «OK» не подтверждает конкретную версию. Она выполняется после подтверждения до установки и повторно после неё. Default max_bytes=256 MiB, timeout_seconds=600; допустимый timeout 30–1800. Весь snapshot связан с хешем подтверждения. Изменение/удаление записи отменяет невыданный план, изменение другого пакета — нет.

## Разрешение агента

Новая отдельная идентичность с `--allow-installations` при enrollment и каждом запуске. Флаг независим от `--allow-commands`: не нужно давать право произвольных команд ради утверждённых пакетов. Существующая identity не расширяется этим флагом скрыто; нужен новый согласованный enrollment. Повышенные права автоматически не выдаются.

## Работа оператора

Главная страница — «Основной раздел» с одним окном задания агенту. Для точного выполнения установки откройте «Устройства» → выбранный узел → «Установка ПО», выберите пакет/версию. До подтверждения видны источник, SHA-256, параметры запуска, timeout, проверка и порядок удаления. Отклонение не запускает ничего. Обычный модельный ответ пока сам не исполняет действия; естественно-языковой tool planner — последующий этап.

- `verified`: нужная версия подтверждена после успешной установки.
- `already_installed`: нужная версия была подтверждена до запуска, скачивание/установка пропущены.
- `reboot_required`: код 3010 и версия подтверждена; PSLC Agent перезагрузку не вызывает.
- `verification_failed`: нужная версия не подтверждена, даже если процесс вернул 0/3010.
- `integrity_failed` / `download_failed`: установщик не запущен.
- `outcome_unknown`: эффект/завершение установщика требуют сверки; слот удерживается и повтор не выполняется автоматически.

1641 не приравнивается к проверенному успеху: установщик сообщил уже инициированную перезагрузку, нарушив ожидаемую suppression-политику. Нужен отдельный разбор пакета. Для произвольного EXE нельзя гарантировать, что он соблюдает объявленные флаги; разрешение конкретного пакета требует проверки на выбранном стенде.

## Данные и миграция

Схема v2 сохраняет старые устройства/credentials/задачи, добавляя installations_enabled=false и package_meta. Неизвестная версия схемы отклоняется. Код/параметры и полный вывод остаются временными; сохраняются только типизированные ID/версия/хеш/коды/флаги. Дистрибутив временно сохраняется как артефакт и удаляется по окончании, не как архив журналов. Штатные журналы ОС/самого установщика вне PSLC Agent подчиняются правилам организации. Автоматического uninstall/rollback нет: инструкция доступна до подтверждения, само удаление — отдельное решение.

## Проверка и границы

Тесты выполняют реальные version probes и изолированный Python fixture, создающий только файл версии в pytest tempdir. Подменяется вызов системного installer process; это **не** установка настоящего MSI/EXE/DEB/RPM. SHA-256, загрузка, API/подтверждение/очередь и итоговая проверка проходят обычные стадии. Для пилота нужен выбранный дистрибутив/узел и организационный допуск; реальные package managers/пакеты ещё не проверены.

Источники: [Microsoft installer options](https://learn.microsoft.com/en-us/windows/win32/msi/standard-installer-command-line-options), [MSI return codes](https://learn.microsoft.com/en-us/windows/win32/msi/error-codes), [Debian dpkg](https://manpages.debian.org/bookworm/dpkg/dpkg.1.en.html), [RPM](https://rpm.org/docs/6.0.x/man/rpm.8). SHA-256 — обязательная привязка к утверждённым байтам, проверка издательской подписи в этом изменении не реализована.
