# Сетевое развёртывание

По умолчанию API слушает loopback. Для подключения удалённых узлов администратор должен отдельно согласовать среду, цели, права, HTTPS/PKI и узкие private CIDRs. Не открывайте административный интерфейс напрямую в Интернет.

## Конфигурация

Ниже только шаблон. Замените placeholders в защищённой конфигурации своей установки; не сохраняйте реальные секреты в Git или чат.

```text
PSLC_AUTH_MODE=accounts
PSLC_PUBLIC_ORIGIN=https://<имя-сервера>:8787
PSLC_API_HOST=<private-IP>
PSLC_PILOT_NETWORK_ADMITTED=1
PSLC_PILOT_IT_REFERENCE=<решение ИТ>
PSLC_PILOT_SECURITY_REFERENCE=<решение ИБ>
PSLC_PILOT_ALLOWED_CIDRS=<узкие согласованные private CIDRs>
PSLC_TLS_CERT=<chain PEM>
PSLC_TLS_KEY=<защищённый private key PEM>
PSLC_DATABASE_URL=<приватный PostgreSQL URL>
```

Accounts требуют корректный HTTPS public origin для сетевого режима: cookie и CSRF используют этот origin. Сертификат должен соответствовать SAN/hostname и доверенной цепочке. Не обходите проверки источника, схемы и TLS с помощью непроверенного proxy.

В новой пустой базе создаётся общеизвестный admin/admin. Смените пароль до сетевого использования. Перезапуск и обновление не сбрасывают существующий пароль. Для обычной работы назначайте минимально необходимые роли и scope.

## Узлы и ограничения

Настройте enrollment profiles и конфигурацию по NODE_MANAGEMENT.md. Root URL берётся из PSLC_PUBLIC_ORIGIN. При частном CA установите доверенный CA на каждом узле. Узловые credentials и identity уникальны; не копируйте их между устройствами.

Сохраняются независимые local opt-ins, точное подтверждение планов и ограничения очередей. Сетевой флаг не выдаёт административные права узлу. Preflight, декларация плана пилота и успешные fixtures не являются допуском к production.

До использования отдельно проверьте сетевую доступность, сертификаты, права служб, отзыв доступа, резервирование и восстановление в выбранной среде. Не отключайте политики безопасности ОС ради запуска runtime или прохождения теста.
