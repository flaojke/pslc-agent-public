# Работа специалиста ИТ

После входа открывается «Основной раздел» с одним промптом. По умолчанию логин/пароль локальной УЗ: системный admin/admin создаётся один раз. «Учётные записи» — смена своего пароля; администратор создаёт/настраивает сотрудников и scopes. AD/SSO отложены. Не вводить пароль/key в задание агенту. Старый token mode только при явном выборе development configuration.

Примеры: «Проверь состояние узла pc-01»; «Расследуй ошибки на pc-01 за последние60минут»; «Установи <package-id> версии<version> на pc-01»; «Найди инструкцию <ошибка/сервис>». Без endpoint модель не имитируется: ограниченная локальная грамматика или источники без LLM-ответа. Для Linux диагностики явно указать systemd unit.

План: проверить все цели/команды/параметры/версии/постусловия и hash; подтвердить весь неизменный план. Выполнение начинается только после предусмотренного подтверждения и текущих прав. Смена каталога/прав/TTL требует новой подготовки. Статусы успех процесса/проверенное постусловие/проверенный сбор различаются. Unknown блокирует повтор до внешней сверки. Cancel прекращает новые шаги и не отменяет уже возникший эффект.

«Устройства» — отдельные точные формы и readonly каталог ПО. Capabilities commands/installations/diagnostics включаются отдельным допуском узла, не текстом промпта. Чужие metadata могут быть видны аудитору в scope, чужие исходный код/вывод/гипотезы и подтверждение недоступны.

«Знания» сейчас показывает, что Confluence отложен. Будущий персональный коннектор поддерживает live источники/version и временный answer с citations. Проверять применимость OS/service/version. Временный ответ удаляется≤120s и скрывается при повторной live проверке ACL/version. Reviewer подтверждает применимость ссылки, не автоматическую правоту модели.

«События» — только metadata/статистика. Platform_admin дополнительно видит DB/readiness. Missing/configured/declared не означает принятый пилот; production false. Политики/согласования меняются по принятому процессу, не через модель.

После задачи можно скачать безопасную заготовку OpenSpec; дальше ручной review/spec/design/tasks/checks. История не хранит исходные журналы/полный вывод/код/model context. После перезапуска старый план не восстанавливается; подготовить новый с действующим подтверждением.

Подключение/настройки машин в UI — NODE_MANAGEMENT.md, модели Open WebUI — OPENWEBUI_CONNECTION_GUIDE.md.
