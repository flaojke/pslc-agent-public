# Поставка агента — 0.7.0

Сборка: `.venv/Scripts/python.exe scripts/build_agent.py` на Windows; `docker build -f deploy/Dockerfile.agent -t pslc-agent-native-qa:0.7.0 .` на Linux-контейнере. Native PyInstaller6.22.3, pywin32 312, requirements.agent.txt/requirements.build-windows.lock.txt. `dependency-inventory.json` и licenses входят в подписываемый bundle; это inventory, не аудит уязвимостей. Linux image pinned digest, build context whitelist исключает .local и операторские credentials. SDK Windows ssl.py требует codex-rejected-cas.pem: build включает штатный trust asset, не меняя проверку TLS.

API остаётся127.0.0.1:8787. PSLC_TLS_CERT + PSLC_TLS_KEY включают HTTPS; одна половина конфигурации запрещена. Агент --ca-file или ca_file strict config использует системное SSL chain/hostname validation; verify=false нет. HTTP допускается только loopback. mTLS и сетевой production ingress не заявляются реализованными.

Config: deploy/agent-config.example.json. state/CA — абсолютные пути, config не содержит credential, все capabilities false. Одноразовый enrollment отдельным --enroll с getpass. Директория state заранее доступна только владельцу/службе; Linux0600/UMask0077, Windows NTFS ACL назначаются администратором. Не помещайте state внутрь versioned bundle. Python/Node/PowerShell/cmd — внешние runtimes: standalone Python в bundle не является интерпретатором произвольных скриптов, при отсутствии runtime возвращается prerequisite_missing.

Подпись: `python -m agent.delivery sign --bundle ... --version 0.7.0 --platform windows-x64 --key-file <protected private PEM>`; `verify --bundle ... --trusted-key <pinned public PEM>`. QA-only keygen создаёт явно помеченные ключи, которые не следует доверять в организации. Передача public key — отдельный доверенный канал. Detached Ed25519 не заменяет корпоративный Authenticode/ИБ допуск.

Обновление: `stage --bundle ... --release-root ... --trusted-key ...`, остановить агент и сверить неизвестные эффекты, затем `activate --release-root ... --version ... --expected-digest <проверенный digest> --state <реальный путь identity> --trusted-key ...`. Сверяются все файлы, platform, exactdigest и lock той же identity; downgrade/extra/missing/link/traversal запрещены. current.json атомарен, старые versioned directories сохранены. Интерактивный `launch` перепроверяет подпись/files перед запуском текущей версии с внешним config. Не менять key/digest по инструкции модели. Нет автоматического remote self-update, autoretry/rollback.

Windows: standalone `--service` — настоящий SCM dispatcher/ServiceFramework. На выбранной машине администратор назначает LocalService read на verified bundle/config/CA, modify только на state/workdir; затем deploy/install-windows-service.ps1 -AgentExe <абсолютный exe>. Скрипт создаёт demand service, не запускает её. Update требует Stop и явное -Update, изменяет SCM binPath на проверенную versioned сборку. Pointer активации не переписывает SCM автоматически. Разрешения администратора нужны для регистрации службы; расширенные node capabilities сами не включаются. Обычный console exe нельзя регистрировать без --service. Реальный SCM start/stop ещё не проверен на выделенной машине.

Linux: заранее создать service account pslc-agent, установить versioned bundle в /opt/pslc-agent/versions/0.7.0, config в /etc/pslc-agent, state в /var/lib/pslc-agent; deploy/pslc-agent.service. Выполнять daemon-reload/enable/start только на выбранном пилотном узле. Обновление — stop, verify/stage, изменить ExecStart на проверенную версию, daemon-reload/start. Unit имеет least privilege, ProtectHome/System, NoNewPrivileges, core dumps disabled. Это может ограничить административные операции: нужный сервисный account/допуск выбирает ИБ, privilege escalation автоматически нет.

Stop прекращает новые poll и ждёт ограниченную текущую операцию; Linux TimeoutStopSec2100, Windows STOP_PENDING обновляет checkpoint. Принудительный OS shutdown/kill может потерять RAM pending result; backend outcome_unknown сверяется вручную. Instance lock не даёт запустить две копии с одним state. Отзыв credential блокирует poll/result независимо от TLS.

Официальные источники: https://www.pyinstaller.org/en/stable/ (native builds), https://github.com/mhammond/pywin32/blob/main/win32/Lib/win32serviceutil.py (ServiceFramework). Реальные Windows/Linux binary health проверяются отдельно; Linux container не удостоверяет systemd или корпоративную ОС/PKI.
